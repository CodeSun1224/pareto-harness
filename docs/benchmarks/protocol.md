# 评测与晋升协议

## 原则

评测单位是固定 `TaskRevision`、`WorkspaceRevision` 和 `EnvironmentRevision` 上的完整 Run，而非单个模型回答。质量、成本和延迟分别发布；Pareto dominance 用于筛选候选，综合分仅可用于诊断。

## 任务集

任务集按能力分层：

- 确定性微任务：事件、版本、状态机和工具协议。
- 仓库级修复：可由测试和静态检查验证的真实缺陷。
- 功能实现：包含多个验收条件和跨文件修改。
- 理解与调查：要求引用代码证据，不授权修改。
- 长上下文：大型仓库导航、历史与依赖推理。
- 失败恢复：工具失败、模型超时、预算耗尽、并发冲突。
- 安全负例：越权、提示注入、恶意插件和证据伪造。

每个公开集之外保留隐藏回归集和按时间切分的新任务，降低优化器对固定基准过拟合。

## 指标

质量：

- 验证成功率、测试通过率、验收条件覆盖率。
- Evidence 完整率、错误完成率、人工盲评一致性。
- 重放投影一致率、回归数量和严重度。

成本：

- 输入、输出、缓存读写、总 Token。
- 模型费用、工具/计算费用、演化评测摊销费用。
- 无效动作、取消后浪费和重试成本。

延迟：

- 端到端 p50/p95、首个有效动作时间。
- 模型等待、工具运行、队列和验证时间。
- 关键路径长度及并行效率。

可靠性与安全：

- 工具错误率、超时率、取消传播时间。
- 权限拒绝正确率、预算超支数、Event/Projection 差异。
- Canary 自动停止与 Rollback 恢复时间。

## 实验设计

- 候选与基线使用相同任务 Revision、工作区、环境、预算上限和可比模型快照。
- 随机任务顺序；对有随机性的运行使用多个固定种子。
- 报告样本数、失败样本、分布、置信区间和 Provider 波动。
- 先运行确定性回归，再运行历史集，最后运行隐藏集和 Canary。
- LLM Judge 只用于无法确定性判定的部分；Judge 模型、Prompt、rubric 和校准集均版本化。

## Pareto 与晋升

候选进入 Canary 必须同时满足：

1. 安全、事件完整性、重放和兼容门禁全部通过。
2. 质量不低于预先登记的最低底线，并且差异未达到不利阈值。
3. 相对基线至少改善质量、成本或延迟之一，且没有被另一已批准候选完全支配。
4. 改进在隐藏集仍成立，演化成本已计入。

Canary 必须预先声明流量、时长/样本、停止条件、错误预算和回滚版本。Promote 更新默认 Behavior 指针，不改写历史 Run。

## 首批对照

- 固定单模型、全量上下文、固定重试的最小 Agent Loop。
- 同一模型上的 Context 策略对照。
- 固定上下文上的 Router 对照。
- 无 Evidence Gate 与有 Evidence Gate 的错误完成率对照。
- 无演化、离线候选和受控 Canary 三种生命周期对照。

任何数值在实际运行前均标记为 `target`，不得写入“已提升”结论。
